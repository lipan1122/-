### P0-3 AR 账户总账与台账双边同步

**修法**：入账、还款、转账、核销在**同一事务**内同步 4 张表（`ar_ledgers` / `ar_accounts` / `ar_transactions` / `ar_write_offs`）。

| 操作 | 账户 | 流水 | 台账 | 核销 |
| --- | --- | --- | --- | --- |
| 挂账 | +X | POST +X | 新增 CHARGE | — |
| 入账 | +X | POST +X | 新增 CHARGE（本轮补） | — |
| 收款 | −X | PAY −X | FIFO `settled_amount`（本轮补） | — |
| 转账 | 源−X / 目标+X | TRANSFER ±X | 源 FIFO + `TRANSFER_OUT` 审计；目标 `TRANSFER_IN` 新台账（本轮补） | — |
| 核销 | −X | WRITE_OFF −X | FIFO `settled_amount`（本轮补） | 按分摊逐条，指回台账 |
| 失败/超额 | 全部回滚 | | | |

**`ar_ledgers` 没有源/目标概念怎么处理**：不用「一笔转账记录」硬塞（它主键是 `company_id`，`amount/settled_amount` 只表达应收/已收，且 `test-member-ar` 硬断言 `0 ≤ settled ≤ amount`，负行会判非法），改用「源方 FIFO 冲减 + TRANSFER_OUT 审计行（净额 0 只留痕）+ 目标方 TRANSFER_IN 新台账」。

**证据**：`test-ar-ledger-sync.mjs` **58 断言**。

### 部署踩的坑（已修）

`backfill-stay-guest-id.mjs` 用 `sudo` 跑，创建的 `-wal`/`-shm` 归属 **root**，
而服务跑在 `ubuntu` 用户 → 服务写库报 `attempt to write a readonly database`，登录失败。

**修**：`sudo chown -R ubuntu:ubuntu /opt/pms/data` + 重启。

**教训**：部署脚本里所有 `sudo node scripts/...` 之后都应该 `chown` 一次 `data/`。

## 附：这轮的方法论收获

**「写死数字」在并行开发下必然假红。**

这轮三个测试因为写死数字而红：
- `test-schema-fresh-install` 的表数：90 → 91 → 92 → 93（4 次变化）
- `test-security-fix` 的无鉴权接口列表：3 → 10 → 16（3 次变化）
- `test-room-action-idempotency` 的 `payments` 列清单（加了 `kind` 就红）

全部改成**弹性断言**：
- 表数 → 「包含 19 张关键表 + 总数 ≥ 90」
- 接口 → 「`mini/` 前缀匹配 + `expectedPublic` 精确匹配」
- 列清单 → 「`request_id` 在列里，尾部允许追加」

**真正要守的是「意图」，不是「快照」。** 断言写意图（关键表都在、没有预期外的裸接口、幂等键在列里），
而不是写「今天有 92 张表」—— 后者只能证明「我改过测试」。

另一个收获：**`sudo` 跑脚本会污染文件归属**。VPS 上服务以 `ubuntu` 运行，
任何 `sudo node scripts/x.mjs` 之后都要 `chown` 一次 `data/`，否则下一个请求就写不了。
